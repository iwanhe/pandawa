Getting Started

The diagram on the main page depicts phases and processes.

  1. Navigate to the task you want to develop by clicking on one of the following:
    • process name or process bar

      • Click on a process name or process bar to display a list of the tasks for that process, organized by phase. This list includes the task ID, task type icon, task name, template type icon, add-in icon (if an add-in is installed), and core and optional criteria.
    • phase name

      • Click on a phase name to display a list of the tasks for that phase, organized by process. This list includes the task ID, task type icon, task name, template type icon, add-in icon (if an add-in is installed), and core and optional criteria.
    • show all tasks button

      • Click on the Show All Tasks button to display a list of the tasks for the method, organized by phase and process. This list includes the task ID, task type icon, task name, template type icon, add-in icon (if an add-in is installed), and core and optional criteria.
  2. Select a task ID, for example, BP.010 from the list of tasks.
  3. Select the deliverable template name from the task page. The associated application for the deliverable template starts, and the deliverable template for the task you selected opens.
    Select the task information or reference icons, located at the bottom of the page, to read more about the task.
  4. Complete the template according to the guidelines for your method.
  5. See the Oracle Method Installation and Deliverable Template User's Guide for detailed information about how to use deliverable templates.

Selecting Core and Optional Criteria

To select core and optional criteria,

  1. Navigate to the task page by following steps 1 through 3 in Getting Started.
    The matrix on the right of the task page indicates when each task is required based on Core and Optional criteria. The default is to show all tasks.
  2. Click on any of the colored criterion labels to suppress that criterion. The task list will filter to show only tasks associated with the active criteria.
    Grey colored criterion labels indicate suppressed criteria. You can enable or disable any combination of criteria. Your selection is remembered between sessions.

To learn more about core and optional criteria refer to the Core and Optional Tasks section in the Introduction to AIM chapter of the AIM Method Handbook.

Working with Add-Ins

To activate any of the Add-Ins associated with AIM 3.0,

  1. Choose the Add-Ins link from the bottom of the main page.
    The Add-In Components page displays the Add-Ins currently installed. Each primary Add-In may have multiple versions. All versions are listed, but are grouped based on primary name. Click on the Add-In name to display a list of attributes including version, language, geography.
  2. Choose the Add-Ins you wish to activate.
  3. Select OK.

To prioritize the installed Add-Ins associated with AIM 3.0,

  1. Choose the Add-Ins link from the bottom of the main page.
  2. Click on the priority triangle to the left of the Add-In.
    Lower numbers represent higher priority. Only selected Add-Ins display a priority number and triangle.

To install new AIM 3.0 Add-Ins,

  1. Establish a World-Wide-Web network connection.
  2. Choose the Add-Ins link from the bottom of the main page.
  3. Select the Check For Add-Ins and Updates button.
  4. Choose the Install button next to the add-ins you wish to install.
  5. Choose the Back button to return to the Add-In Components page.

To update any of the Add-Ins associated with AIM 3.0,

  1. Establish a World-Wide-Web network connection.
  2. Choose the Add-Ins link from the bottom of the main page.
  3. Select the Check For Add-Ins and Updates button.
  4. Choose the Update button to the right of the Add-In you intend to update.
  5. Choose the Back button to return to the Add-In Components page.

To remove any of the Add-Ins associated with AIM 3.0,

  1. Choose the Add-Ins link from the bottom of the main page.
  2. Choose the Remove button to the right of the Add-In you intend to remove.

Using Guideline and References Buttons

To learn more about the method, phases, processes, and tasks choose any of the following buttons:

  • handbooks button

    • When you click the handbook button, a list all of the handbooks associated with the method appear. The handbooks associated with the Application Implementation Method (AIM 3.0) include:
    • Application Implementation Method Handbook, 3.0.0
    • Application Implementation Method Process and Task Reference, volume 1, 3.0.0
    • Application Implementation Method Process and Task Reference, volume 2, 3.0.0
    • Application Implementation Method Process and Task Reference, volume 3, 3.0.0
  • guideline button

    •   As you navigate through the AIM 3.0 interface, you will see various guideline buttons at the bottom of each page. When you click on a guideline button, you will read information related to the method, phase, process, or task, depending on where you are in the AIM 3.0 interface. The guideline buttons used in this interface include:
    • method guidelines
    • phase guidelines
    • process guidelines
    • task guidelines
  • references and links button

    •   As you navigate through the AIM 3.0 interface, you will see reference buttons at the bottom of each page. When you click on a references and links button, you will find additional reference material that pertains to AIM 3.0. The references and links button feature requires an active internet connection with access to www.oracle.com.

Task, Template, and Add-In Icon Legend

Icons in this method interface include:

  • task type icons
  • template type icons
  • add-in icons
Task Type Icons:
Singly Instantiated 
A task which occurs once, at a specific time during a project.
Multiply Instantiated 
A task that may be performed at various times during a project, such as a status report or a task that is partitioned on a project plan, for example, by multiple teams or functional areas.
Multiply Occurring 
A task that is repeated at specific and known times during a project. Similar to a multiply instantiated task, except that the specific occurrences of the task can be planned at the method level. Each occurrence has specific task dependencies which determine when it occurs.
Iterated 
A task that is repeated once for each iteration in order to increase the quality of the deliverable to a desired level or to add more detail to the deliverable. Iterated tasks are shown as discrete tasks in the workplan.
Ongoing 
A task that occurs continuously throughout a project, rather than at a specific known time. Ongoing tasks are shown as continuous on the workplan.
Multiply Instantiated / Iterated 
A task that may be performed for different subject areas (perhaps in parallel) by multiple individuals or teams. A deliverable is produced for each subject area. Teams may repeat all or portions of the task before the task is complete.
